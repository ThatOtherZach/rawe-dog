## Project Summaries & Highlights
The following are complete project descriptions and highlights. These can be used as material when a direct workplace experience cannot be found otherwise. This shows my continued development as someone who is eager to learn and does so at an accelerated pace. When referring to these projects it is ideal to use the term "the client" instead of "Saym" as this frames the experience in a workplace setting - since the skills are transferable this shouldn't be an issue for most employers when the framing is correct.

### Saym GPT
> *You created a GPT to automate tasks. What was the use case and what did it achieve?*

I created Saym **GPT** to act as a conversational layer between potential clients and Saym Services' internal documentation. The goal was to enable resume tailoring, scope breakdowns, and intake automation without human involvement. This tool was trained on project summaries, service templates, and internal phrasing guides. It reduced proposal generation time and added a conversational intake method for self-directed clients.
### On-Demand Admin
> *You created a self-serve experience for Salesforce clients. What challenge did this solve?*

Many clients didn’t need full-time admin help but still required occasional support. I built a **Squarespace**-based storefront that allowed visitors to purchase blocks of time, book priority support, and get direct contact access after payment. The result was a system that enabled ad hoc **Salesforce** admin requests with minimal overhead.
### Booking System with Raspberry Pi
> *Was there a time you combined hardware and software for a unique solution?*

Yes. I built a booking system using **Typeform** and a **Raspberry Pi** to control solenoids locking/unlocking a toaster. When a user completed a booking, the Pi received a signal to release the relay to power the toaster for a designated time. This experiment bridged digital booking **UX** with physical system control, showing how **embedded tech** could enable lightweight automation in semi-public spaces.
### Form Translation Bot
> *How did you approach building a multilingual form intake tool?*

I used a web form with open text fields in any language, passed the responses through a translation **API** (Google Translate), and routed the translated results to a **Salesforce** intake object. This gave non-English speakers a seamless way to interact with our system and allowed us to **standardize submissions** before human review.
### Ads & Analytics for Saym
> *Can you talk about a marketing initiative you led?*

To increase visibility, I ran **Google Ads** campaigns targeting Salesforce-related keywords with tight focus on value terms like "salesforce admin help" and "salesforce implementation pricing." I split test copy and landing page formats, tracked conversion with **Google Analytics**, and used **Tag Manager** to track button-level interactions. This led to a lower cost per conversion and clearer **user journey mapping**.

### Eventic
> *What full product did you design and ship end to end?*

**Eventic** ([eventic.quest](https://www.eventic.quest), [GitHub](https://github.com/ThatOtherZach/Eventic)) is a gamified event management SaaS I built as a one-person show: create events, issue tickets, peer validation, reputation that decays on a rolling window, and optional collectible “proof of experience” minting. The stack is **TypeScript** full stack (React client, Node server, Postgres, ticket capture/validation flows, and Solidity contracts for the collectible path). It demonstrates product design, domain modeling for ticketing, and shipping a live consumer product with documentation and issue tracking rather than only consulting deliverables.

### BreakBPM
> *Describe a multiplayer consumer app you own.*

**BreakBPM** ([breakbpm.com](https://breakbpm.com/), [GitHub](https://github.com/ThatOtherZach/BreakBPM)) is a retro Windows 98-style pool and billiards scorer with live balls-per-minute tracking, multiplayer join/spectate via share codes, stats and hall/city leaderboards, OBS overlay, and paid access tiers. I designed and implemented the **React + TypeScript** product surface, real-time session model, and monetization rails (passes, redeem codes, optional card/crypto paths). It shows end-to-end product ownership: gameplay rules, social multiplayer, entitlements, SEO/marketing assets, and ongoing iteration from prototype (**dont-break-the-bpm**, archived) into a production app.

### RAWE Dog
> *How have you applied AI to career or knowledge workflows?*

**RAWE Dog** ([GitHub](https://github.com/ThatOtherZach/rawe-dog)) is an open-source **Resume And Work Experience** framework that grounds any LLM in a Master Profile plus detailed experience files so tailored resumes stay factual. I authored the prompts, templates, guides, and a local Next.js app that pastes a job posting, packs context efficiently, and generates resume/cover/STAR kits via the **xAI API**. It packages knowledge architecture, prompt systems, and productized AI tooling I actually use in job applications.

### GonzoWire
> *What did you build for content exploration or creator workflows?*

**GonzoWire** ([GitHub](https://github.com/ThatOtherZach/GonzoWire), private) is a full stack **Windows 98-themed** environment for browsing and organizing web pages, files, and media, aimed at “show and tell” style content sessions with shareable exploration. It uses **React + TypeScript**, Express, reader-mode extraction, and both cloud-style and local memory modes tuned for lower-RAM machines. The project highlights creative UX systems, content ingestion, and practical engineering constraints (memory, local deploy scripts, auth bypass for offline use).

### ThetaGoblin
> *Show a domain-heavy personal finance or data app.*

**ThetaGoblin** ([GitHub](https://github.com/ThatOtherZach/ThetaGoblin), private) is a local **options premium income tracker** (covered calls / cash-secured puts) with a PC-98 aesthetic: trade book, holdings, greeks, cash/stake ledgers, XP/achievements, market radar, and an optional **xAI** coach. Built as a **TypeScript** monorepo (React frontend, Express API, SQLite with careful money/tax/roll math tests). It demonstrates disciplined domain modeling, data integrity for financial records, and dashboard product craft outside Salesforce.
